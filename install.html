Where this instance lives

Both names are derived, not typed. The Matrix name becomes part of every MXID and room alias on this server, so it cannot be changed after the first start without breaking federation identity.

A reachable host with public DNS and Let's Encrypt certificates.

The domain you control DNS for, without a scheme or trailing dot. On the host, hostname -d prints it.

Distinguishes several bytEM instances sharing one domain.

Both names need to resolve here, with TCP 80, 443 and 8448 reachable, by the time you run the installer — 80 for certificate issuance, 8448 for federation.

Names under .localhost are reserved for loopback by RFC 6761, and glibc and systemd-resolved answer them without any DNS or /etc/hosts entry — so this needs no configuration and works offline. If your resolver is one of the few that doesn't, add one line: 127.0.0.1 bytem.localhost matrix.bytem.localhost.

Certificates are generated locally. certbot.sh --self-signed writes a 30-day certificate for each name with openssl — no Let's Encrypt, no DNS, no reachable ports. Your browser will warn once per name; accept both and it stops asking. For certificates your browser trusts outright, mkcert -install then mkcert bytem.localhost matrix.bytem.localhost into certbot/conf/live/ works too. A local instance cannot federate: Everything inside the stack works — the PWA, the API gateway, the bot, Synapse, Solr and RabbitMQ — and you can publish and index DEIDs, because a DEID is an identifier the stack never fetches. What needs a public name is exchange with other bytEM instances, which requires real TLS on port 8448. Certificates will be self-signed, so browsers warn once per name and you accept both.

Treat a local instance as disposable. Its Matrix name is baked into every MXID and room alias, so it cannot later be promoted to a public deployment — you would install fresh against the real domain.

Two separate accounts

Synapse creates both on its first healthy start. Earlier bytEM releases let the bot double as the test admin; it no longer does, and the installer refuses a configuration that reuses either credential.

A person signs in with this to exercise the instance. Becomes a Synapse admin.

Used only by bytem-be and bytem-bot. Nobody signs in as this.

Allowed in passwords: letters, digits and . _ : / @ % + = , -. Other characters are rejected because they need quoting inside an env file.

Passwords apply on first start only. Synapse creates each account once; re-running the installer with a different password leaves the existing account's password unchanged. To rotate one later, use docker exec bytem-synapse or the Synapse admin API.

Upgrading an existing instance

Nothing to do here if the banner at the top says an existing .env was read — it already happened. This step is the fallback for when it can't be: opening this file directly off disk, or configuring one machine from another. Skip it entirely on a first installation.

Regenerating Synapse secrets invalidates sessions and can break this server's federation identity. REGISTRATION_SHARED_SECRET, SYNAPSE_MACAROON_SECRET_KEY, SYNAPSE_FORM_SECRET and JWT_SECRET must survive an upgrade. So must the database and Solr passwords, or the existing volumes stop opening.
